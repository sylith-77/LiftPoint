# LiftPoint 배포 전용 소스

**문자 발송 대상 선정 시연**. 기존 `streamlit_demo`와 확정 실험 산출물을 보존한 배포 전용 복사본이다. 원래 실험 근거는 `e1d52d29a7ae9145a7637b14a0c3aefc14602b56`, 로컬 앱 게시 근거는 `9a155396dc144d009d05c168a131ee90c8b1fc6c`다.

이번 사용자는 최신 지시로 무료 공개 앱과 별도 공개 저장소에 필요한 최소 산출물을 게시하는 범위를 승인했다. 기존 `MD_files` 저장소의 비공개 상태는 유지한다. 이는 원 데이터의 라이선스가 확인됐다는 뜻이 아니다. 실제 목적지·접속 상태는 배포 작업의 결과 기록을 따른다.

## 코드와 산출물

`streamlit_app.py`는 기존 두 화면·두 모델·재생/실제 추론·고객 검색/상세·집계와 불확실성을 유지한다. 입력은 고정 테스트 40,008명×91개 변수이며 p1−p0와 기존 SHA 동점 규칙으로 정확히12,002명을 선정한다. 실제 발송 여부와 정답은 이 배포 번들에 포함하지 않는다. 신규 fit·튜닝·전처리 적합·성능 평가·bootstrap은 없다.

로컬 최소 번들 작성 명령:

```powershell
.\.local\incrementalvalue-venv\Scripts\python.exe .\streamlit_deploy\build_bundle.py --output .\.local\liftpoint_deploy\liftpoint-v1.zip
```

이 명령은 원본을 읽고 필드만 손실 없이 투영한다. 원자료·시퀀스·학습/검증 배열·전체 고객 분할은 포함하지 않는다. `*.inventory.json`에 파일별 크기·목적·SHA와 원본 SHA, `*.config.json`에 로컬 연결 예시가 남는다. 기존 출력은 덮어쓰지 않는다.

배포 저장소에는 같은 버전의 최소 ZIP을 포함해 서버 재시작/재배포 시 Git 체크아웃으로 다시 확보한다. 휘발성 추출 캐시는 SHA로 구분하고 각 필요한 파일을 내용 해시로 재확인한다. 공개 배포에서는 이 ZIP도 사용자 승인 범위대로 공개 접근 가능한 자료라는 점을 전제로 한다. 비공개 환경에서 재사용할 때는 저장소와 앱 접근을 각각 제한해야 한다.

## 실행 설정

Python3.12를 선택하고 `requirements.txt`의 CPU 의존성을 사용한다. 기존 Windows 가상환경은 업그레이드하지 않는다. Linux CPython3.12 휠의 실제 제공 여부는 배포 준비 시 공식 PyPI 메타데이터로 확인한다.

Streamlit 서비스의 Secrets에 `secrets.example.toml` 형식을 입력한다. 번들 경로·SHA와 실제 배포 코드 커밋을 지정한다. 관리자 토큰은 임의의 긴 문자열이며 코드·커밋·로그·URL에 넣지 않는다. `bundle_path`는 저장소 루트 기준 상대 경로이고 모든 파일명은 대소문자를 구분한다.

로컬 검사는 `LIFTPOINT_CONFIG`로 생성된 JSON 경로를 지정할 수 있다. 배포 환경의 Windows 절대 경로는 사용하지 않는다. 앱의 실행 정보와 오류는 고객 자료·호스트 절대 경로·비밀정보를 표시하지 않는다.

## 배포 환경의 별도 재현 검사

기존 로컬 Windows PASS를 외부 서버 PASS로 사용하지 않는다. 실제 추론은 현재 번들·모델·입력·기준 예측·추론/선정/UI 코드·의존성·실행 환경·배포 코드 커밋의 내용 지문과 연결된 해당 모델의 통과 기록이 있어야 활성화된다.

서버에서 독립적으로 실행하는 명령은 다음과 같다.

```text
python verify_reproduction.py --model all
```

Community Cloud처럼 직접 셸이 없는 환경에서는 관리자만 `?admin=verify` 경로에서 Secrets의 관리자 토큰을 입력한 뒤 **이 배포 환경 재현 검사 실행**을 명시적으로 누른다. 같은 독립 CLI를 별도 프로세스로 실행하며 일반 방문·고객 선택 때 자동 검사하지 않는다. 관리자 토큰을 알지 못하는 방문자는 이 명령을 실행할 수 없다. 캡처된 stderr와 원문 로그는 화면에 출력하지 않고, 허용된 집계 JSON만 표시한다.

검사 기준은 기존과 동일한 `atol=1e-6, rtol=0`이며 확률 오차와 별개로 내부 고객 ID 선정 집합이 정확히 일치해야 한다. 두 확률 순서·LR 구매 클래스 열·`training=False`·고정 전처리·전체 고객/변수 순서를 확인한다. 실패한 모델은 비활성화하고 정상 재생은 유지한다. 고객 상세 변경으로 전체 추론을 반복하지 않는다.

서버 로컬 검사 기록은 재시작으로 사라질 수 있다. 같은 실제 서버에서 검사한 뒤 관리자 화면의 집계 기록을 서비스 Secrets의 `[deployment_verification] records_json`에 보존할 수 있다. 로컬 최신 기록이 없을 때만 이를 읽고, 현재 파일/코드/배포 커밋/환경 전체 지문이 일치하는 모델만 활성화한다. 로컬 실패 기록이 있으면 과거 저장 PASS로 대체하지 않는다. 저장 기록도 달라진 환경에서는 무효이므로 Windows 기록을 복사해 쓰면 활성화되지 않는다. 번들은 저장소에서 다시 확보하며 무료 자원 또는 환경 차이로 검사에 실패하면 기준을 완화하지 않는다.

## 발표 해석

이 앱은 기존 최종 테스트 고객의 사후 시연이다. 확정 집계 CSV·JSON만 읽고 성적을 다시 계산하지 않는다. DL−ML 선정 이득 차이의 점추정은+0.4501%p, 기존95%구간은−1.0374~+1.8991%p다. DL의 점추정은 높았지만 구간에0이 포함되어 확실한 우위를 확인하지 못했다는 해석을 유지한다. p0·p1은%, 증가분은%p, 구매 요약은 원래 단위이며 확인되지 않은 통화 단위를 붙이지 않는다.

배포 성공·공개 URL·원격 재현 결과·서비스 자원 점검은 실제 서비스에서 확인한 결과만 별도 배포 기록에 남긴다. 이 준비 소스 자체는 배포 완료 증거가 아니다.
